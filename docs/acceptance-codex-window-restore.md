# Codex 隐藏窗口导致恢复歧义

日期：2026-10-31。基线为 `origin/main` 的 `dfe6b5066d2ec17065144904d638cbca1a58b475`；本次修复随客户端 0.1.11 于 2026-11-01 公开发布，不改变 `v0.1.10` 标签或安装包。版本安排与发布后复测项目见 [0.1.11 验收记录](acceptance-0.1.11.md)。

## 只读诊断

实际安装客户端为 0.1.10，日常 Codex MSIX 为 `26.1027.3384.0`。只读枚举该 Codex 进程的 Win32 顶层窗口，没有激活、恢复、关闭或修改日常窗口。原有 `is_main` 条件命中两个候选：

| 窗口 | Win32 style | Win32 可见 | 最小化 | 原规则 |
| --- | --- | --- | --- | --- |
| Chromium 隐藏窗口 | `0x04C70000` | 否 | 否 | 命中 |
| 日常主窗口 | `0x34C70000` | 是 | 是 | 命中 |

两个窗口的 PID 相同，类名均为 `Chrome_WidgetWin_1`，owner 和 DWM cloaked 均为 0，扩展样式均为 `0x00240100`。旧代码将所有候选一起计数，因数量为 2 而报告“无法唯一确认可恢复的主窗口”；这不是对当前未登录、网络异常或没有运行 Codex 的判定。

## 修复与验证范围

在完整原有窗口条件之后，优先选择唯一 Win32 可见候选，包含已最小化窗口。多个可见候选继续拒绝；全部隐藏时只恢复唯一候选。保留真实进程句柄、创建时间、包身份、用户/会话、回环监听者、精确页面和输入前后重枚举检查。错误提示分别说明没有候选、多个可见候选、多个隐藏候选。

新增原生回归覆盖隐藏 Chromium 窗口并存时恢复可见/最小化主窗口、保留最大化、保持隐藏窗口不显示，以及多个可见主窗口（包括最小化窗口）继续拒绝。既有隐藏唯一恢复、无边框、辅助窗口及归属变化测试保留。

前一轮默认 PATH 没有 `cargo`，未能启动原生回归。合并用户中心至 0.1.11 时，在仓库忽略目录发现了既有便携 MSVC Rust 工具链；用 `rustc --test --edition=2021` 直接引入生产 `managed_window.rs` 和 `owned_process.rs` 及原有测试，6 项窗口回归和 6 项进程归属回归通过，2 项子进程辅助入口保持 ignored 并由父用例调用。没有替换窗口或身份实现，也没有修改系统/用户 PATH。

完整 Cargo/Tauri 构建和原生安装器仍由既有 CI 与发布门禁验证；原生模块通过不等于完整安装包或真实 Codex 通过。代码差异、Markdown 相对链接和 `git diff --check` 已检查。本专项只读诊断时没有安装或发布客户端；后续固定标签发布与实装见版本验收。未在日常 Codex 上执行恢复输入或侧栏注入；发布后的安装版复测仍按[版本验收记录](acceptance-0.1.11.md#窗口恢复的安装版复测)执行。
