# 0.1.11 版本验收记录

状态：开发候选，尚未发布；客户端 0.1.11，服务器 0.1.5-preview.1。准备与独立验收日期：2026-10-31。

本版合并用户中心/服务器治理提交 `cadd9ff` 与既有窗口恢复准备提交 `5501cc6`，两者基于 `origin/main` 的 `dfe6b50`。远端准备分支统一为 `codex/fix-codex-hidden-window`；账号功能先在 `codex/account-center` 验收。当前公开标签和本机安装版仍为 0.1.10，发布标签、最终产物摘要与安装证据待实际完成后补充。

## 纳入范围

- 用户中心、账号安全、设备会话、主题入口迁移；邀请制用户治理、SMTP、限时空间接管和持久审计。
- Codex 隐藏 Chromium 窗口导致恢复歧义的修复，及原生正负回归用例；只读窗口元数据与身份边界见[专项记录](acceptance-codex-window-restore.md)。
- 根客户端、网页、桌面包、Tauri、Rust 包及本包锁文件版本统一为 0.1.11；服务器独立为 `0.1.5-preview.1`，新增 `0010_account_center`、`0011_account_recovery_hardening` 增量迁移与 Nodemailer/sharp 依赖。
- [更新日志](../CHANGELOG.md)与[发布说明](release-notes.md#codex-taskboard-客户端-0111待发布)统一记录两项工作。官方 global/thread UI 合成原型继续留在开发工具中，不纳入产品运行时。

## 验收环境与数据

使用 Windows、Node 22、pnpm 10、独立 PostgreSQL 18 `taskboard_test` 数据库、每项测试独立 schema、合成邮箱和浏览器配置。账号 E2E 使用发信替身；另以真实 Nodemailer 对本机受控 TLS/STARTTLS SMTP 接收端验收协议，不向外部邮箱投递。不使用生产数据库、日常 Codex 登录或真实草稿。测试数据库仅绑定回环地址，测试后停止自己的服务并释放端口。

## 重点验收行为

- 没有空间也可进入设置；资料保存、头像裁剪、联系方式可见范围、设备撤销、邀请加入、邮箱确认和密码恢复均使用独立账号。保存失败保留输入，未保存时离开页面或浏览器导航需要确认。
- 停用不能留下失效所有者：创建空间与治理使用同一事务锁，排队请求取得锁后重新检查会话；普通所有者和最高管理员均不能将空间转给已停用成员。并发撤销最高权限必须保留有效最高管理员。
- 接管绑定指定空间与当前网页登录会话，复核到期、撤销和最高权限；Agent 和伴随服务不获后台权限。接管不改变真实成员关系，也不绕过任务状态机及人工验收。
- 接管草稿只保留在当前窗口，任务内容和空间元数据不进入离线快照；退出、到期或撤权清理相关查询和打开任务。本人资料、成员公开资料与头像缓存按服务器和当前账号隔离。
- SMTP 接受、等待和失败明确区分；失败重试有界，队列与加密数据重启后保留；缺少邮件密钥不阻断已有登录。丢失旧密钥后，显式替换 SMTP 密码可使用新密钥恢复配置，不尝试解密旧凭据；旧队列仍不可恢复。旧 `/admin/account` 不能绕过邮箱验证。

## 截图与测试设施

合成数据截图位于本机忽略目录 `.artifacts/acceptance-0.1.11/`：四套主题各有明暗截图，另有 360px 页面和接管提示截图。已检查桌面布局、窄窗口无横向溢出、长中文名称、键盘焦点和头像。CI 在 E2E 后将这些 PNG 与初始化页面截图一并保存在 `server-administration-ui` artifact，仅收集合成截图，不包含邮件正文、凭据或数据库文件。

测试设施发现并修复了回环请求被互联网代理截获、Windows 临时 PostgreSQL 退出码丢失/残留进程的问题。浏览器测试仅在测试进程补充 `NO_PROXY`；Windows 使用持有的进程句柄和 `pg_ctl` 有界停止自己的测试数据库。故意失败的测试验证返回非零退出码及端口释放。未放宽宿主身份、版本或权限检查。

初轮数据库回归有一次 CLI 运行超时，独立重跑及后续完整相关批次通过。浏览器初轮暴露邀请接受后页面重载与输入竞态，测试现等待登录页就绪；新增回归发现取消浏览器导航后路由仍卸载表单的问题，现由路由在更新状态前执行可取消的离开检查，保留输入。

浏览器测试的服务端均运行在独立 Node 进程，避开 Playwright 模块加载器中的版本库加载错误，保留实际版本检查。接管隐私直接覆盖 `dist/server.js` 生产入口；需要邮件替身的用户中心/初始化用例通过私有 IPC 控制独立测试服务，不向 HTTP 暴露测试控制接口。初次失败记录不视为通过。

持续验收发现首轮 CI 在生产入口检查失败：校验列表尚未纳入 `0010_account_center`，后续外观、E2E 和离线未执行。现补齐精确列表并增加编译后表结构/默认隐私检查；外观联调的截图容器迁入个人设置，同时将身份故障注入限定为可观测的端点故障，避免多个身份消费者争抢首个故障请求。完整 CI 与最终产物仍继续验收，不将首轮部分通过记为版本可用。

第二轮完整 E2E 162 项通过、2 项在窄窗口边界检查失败。初始断言包含关闭菜单的隐藏控件；新增展开菜单回归后，进一步确认 480px 下菜单确实越出左边界。账号入口现复用已有 Radix 菜单的边界避让、键盘与焦点恢复能力；可见控件原边界断言保留，另覆盖展开菜单的每个选项和 360/420px 侧栏。对应桌面/紧凑窗口 8 项回归通过；截图随 CI artifact 保留，完整流水线继续重验。

安全复核先用真实数据库重现旧网页恢复入口仍返回明文链接（预期拒绝、实际 201），再关闭该入口；新网页流程统一发送邮件，服务器 CLI 应急恢复不依赖 SMTP，新链接 30 分钟有效。独立增量迁移清理旧恢复幂等响应，并验证邀请响应、账号身份、密码和有效会话保留。相关账号及服务器 35 项回归通过。

提交 `3d8ab24` 的 `verify`、`container`、`windows-desktop` 均通过：351 项测试、168 项 E2E、生产迁移/外观/离线、Cargo 与容器部署完成。下载对应安装器和服务端镜像后核对官方 artifact 摘要；安装器 17 个当前载荷文件与本机同源码构建一致，两份 skill 文本仅有可精确还原的 Git CRLF 差异。实际升级会保留两份旧哈希静态资源，逐项确认与原包一致且新入口不引用；原账号与 WebView 数据加密冷备份，安装前后逐文件不变。

上述安装版的原生独立配置暴露 CORS 预检缺少账号身份头：网页直连和同来源侧栏通过，但 Tauri 跨来源个人资料请求被 Chromium 阻断。先补真实 Chromium/真实伴随 HTTP 回归重现失败，再精确声明两个账号头；真实浏览器资料读写、头像读写通过，未知头和未授权来源仍被拒绝，原有伴随权限测试也通过。`3d8ab24` 安装器因此不作为可用交付，修复后的候选继续重建与实装验收。

## 证据边界

当前通过范围为源码、真实 PostgreSQL、独立浏览器与生产网页/服务进程、Windows 随包脚本运行时。没有执行真实 SMTP 投递、生产部署或日常 Codex 宿主操作。

此前默认 PATH 未提供 Cargo，账号及窗口恢复分项验收未启动原生回归。本次合并后找到仓库忽略目录中的便携工具链，在任务自己的 PowerShell 进程设置环境后补跑上述两个原生模块，未修改系统或用户 PATH。完整 `cargo test --locked`、服务端镜像、原生桌面构建、NSIS 安装及最终固定标签产物验收仍以对应 `container`、`windows-desktop` CI 和发布环境结果为准；不把模块测试或已有的随包脚本检查记为完整原生安装器通过。生产构建仍有既有的大 chunk 提示，本次没有关闭该提示。

原生模块复验使用本机忽略目录中的 `native-window-check.rs`，仅通过 `#[path]` 引入上述两个生产文件，执行 `rustc --test --edition=2021` 后串行运行测试。首次完整 Cargo 尝试因指定了不存在的 linker 路径失败；修正到便携工具链已有的 `link.exe` 后可编译。完整依赖冷构建未在本机作为通过结果，完整 Cargo 门禁交由 CI；诊断、编译和模块结果分别保存在 `.artifacts/acceptance-0.1.11/`。

本次按用户要求更新远端 0.1.11 准备分支与变更说明，不部署、不打标签、不上传发布资产或替换本机安装版。数据库与独立加密密钥的备份要求见[用户中心说明](account-center.md#邮件服务)。
