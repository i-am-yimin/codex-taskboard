## 安装与数据边界

标准安装器继续使用既有应用 identifier、固定回环端口和 currentUser 安装方式。单改安装目录不能隔离卸载记录、快捷方式、单实例转发或端口。仅设置 `TASKBOARD_DATA_DIR` 也不能隔离 WebView2 profile；实机测试必须分别隔离并验证两个数据位置。

用户已明确批准 Taskboard 维护窗口。根线程按记录来源精确复核进程身份，原日常 Codex 的 PID、真实进程 FileTime、程序路径和包身份均保持一致；通过原样 0.1.7 的标准退出入口正常退出 Taskboard，没有停止或重启日常 Codex。维护前伴随服务状态为 1 个账号、0 条草稿、0 条 outbox，未发现本机运行日志；WebView 内草稿数量未单独解析，由完整 profile 备份保护。旧版程序 35 个文件、卸载记录和同名快捷方式备份再次核对；正常退出并确认固定端口及原 profile 使用者释放后，真实数据 4 个文件、WebView profile 345 个文件完成一致备份，复制前后源文件及备份逐项 hash 相同。所有敏感备份仅在本机忽略目录。

另用与原程序备份 hash 一致的 0.1.7 companion，在 port0 初始化独立的旧版合成账号和数据/profile，已正常退出；这组路径与 fresh 0.1.8 夹具分开。维护窗口内启动原样已安装 0.1.7，并从真实 WebView2 参数确认使用专用合成 profile。窗口工具将 Taskboard 错误归入 Codex 应用，返回了错误画面；未执行点击、键盘或文本输入。进一步读取被自动审批拒绝后停止该路径，用户随后手动回复已完成合成账号、空间、浅色主题和评论框输入。正常退出时首次即时检查发现 WebView 尚在释放，停止复制；只读观察确认同一次退出的桌面、WebView 和端口均释放后才封存 3 个合成数据文件与 275 个 profile 文件，复制前后及备份完整 hash 一致，没有强杀或再次启动退出流程。

初次要求在旧版评论框输入作为升级草稿基线的选择不成立：固定 `v0.1.7` 源码以及原安装备份中实际引用的 JS 均只把评论放在组件内存，没有评论草稿存储键；封存旧 profile 也未找到指定合成标记。用户输入确认不能证明它在退出前已持久化，不据此判定升级损坏或宣称草稿迁移通过。任务编辑与结果草稿在旧版实际 JS 有存储支持，现另从封存的真实旧版 data/profile 完整克隆专用补验夹具，旧程序备份 35 文件 hash 相同。首个安装版测试实例退出且资源释放后，已从完整备份启动字节一致的真实旧版程序，核对实际专用 WebView 路径、日常 Codex 身份和原安装路径仍为 0.1.8；它是旧程序备份运行证据，不宣称重新安装了旧版本。用户已确认在任务描述输入指定标记并看到未保存草稿；该真实旧版实例经标准入口正常退出，专用数据 3 文件及 profile 296 文件完整封存，源与备份逐项 hash 相同。最终 0.1.8 候选仍须复用同一对路径验证恢复，当前不将基线封存写成升级保留通过。原基线和失败选择的证据保留。

根线程对实际既有服务的公开健康接口进行了一次无凭据只读 GET，响应成功且没有新版本/协作能力声明。0.1.8 配合隔离新服务器的可用性与日常生产可用性分别记录；生产升级必须另有备份、迁移、回退和部署授权，不能由客户端安装授权代替。
