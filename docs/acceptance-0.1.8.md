## 安装与数据边界

标准安装器继续使用既有应用 identifier、固定回环端口和 currentUser 安装方式。单改安装目录不能隔离卸载记录、快捷方式、单实例转发或端口。仅设置 `TASKBOARD_DATA_DIR` 也不能隔离 WebView2 profile；实机测试必须分别隔离并验证两个数据位置。

当前日常 Taskboard 为 0.1.7，根线程只读核对了安装版本、监听进程与原日常 Codex 的进程身份，未停止或重启它们。旧版程序 35 个文件已备份并逐项核对 hash，卸载记录和同名快捷方式另存本机；原数据和 WebView profile 的一致备份仍要等正常退出。独立实机夹具已启动随机回环 API 服务和专用 PostgreSQL 子库，以已验随包 companion 将上游与合成登录持久化到专用数据目录，另备空 WebView profile；没有监听固定端口、启动桌面或访问生产账号。后续若需同机标准安装，先完成可审阅候选及完整备份/回退方案，再取得具体 Taskboard 维护窗口。日常 Codex 登录、项目、聊天与真实草稿保持受保护。

另用与原程序备份 hash 一致的 0.1.7 companion，在 port0 初始化独立的旧版合成账号和数据/profile，已正常退出；这组路径与 fresh 0.1.8 夹具分开。维护窗口内仍须先用真实已安装 0.1.7 建立 UI、主题与草稿基线并正常退出，再原样升级 0.1.8 复用该对路径验证保留。当前准备状态不算旧版桌面基线或升级保留已通过。

根线程对实际既有服务的公开健康接口进行了一次无凭据只读 GET，响应成功且没有新版本/协作能力声明。0.1.8 配合隔离新服务器的可用性与日常生产可用性分别记录；生产升级必须另有备份、迁移、回退和部署授权，不能由客户端安装授权代替。
