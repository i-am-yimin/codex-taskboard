# 在 Taskboard 内连接日常 Codex

0.1.4 已公开为未签名开发预览；安装包和校验和见 [README](../README.md#2-安装并登录-windows-客户端)。

打开普通的 Codex Taskboard，在看板标题右侧点击“连接 Codex”。已启用连接的日常窗口会被直接复用；没有运行时，由 Taskboard 打开正常的 Codex 环境。侧栏接入成功后，按钮变为“打开 Codex”，可返回原窗口。登录、项目和聊天沿用原环境。

已经运行但未启用连接的 Codex 仍需正常退出。点击连接后，Taskboard 会显示等待说明；先保存工作并正常退出 Codex，应用随后自动打开原环境并接入，无需再次点击或使用另一个快捷方式。等待可取消，五分钟未完成会结束等待；程序不会结束用户的 Codex 进程。

首次接入成功后，Taskboard 记住“启动 Taskboard 时自动连接日常 Codex”。之后直接打开普通 Taskboard 即可恢复侧栏，在“设置 → 连接与设备”可以关闭。显式关闭后，手动连接也不会重新打开该选项。若后来从其他入口打开了未启用连接的 Codex，仍需按应用内提示正常退出一次，不能热开启已有进程的连接端口。

主界面和设置页共享连接状态及同一次接入请求。独立测试环境保留在设置页的折叠项中；普通浏览器和 Codex 内的看板 iframe 不显示原生连接按钮。旧连接快捷方式保持兼容，但不再是日常使用前提。日常模式的任务草稿仍由用户复制、粘贴并确认发送。

“打开 Codex”支持当前日常 Codex 的无边框窗口，可恢复已最小化的原窗口，保留最大化状态。识别仍要求原进程和页面归属有效，且主窗口唯一；不会选择辅助窗口或独立测试环境。若本机存储无法保存自动连接选项，会单独显示“设置未保存”，本次已接入的状态保持有效；“重试保存”只重试保存选择，不会再次连接或安装侧栏。

连续打开会复用当前侧栏。正在安装或随页面恢复的会话会先等待现有流程；短暂探测失败时只重新校验连接，不会对仍有效的会话重复注入或重载页面。进程或页面归属持续失效时仍拒绝接入。

本地浏览器回归覆盖主界面接入、重复点击只连接一次、普通启动恢复、显式关闭自动连接、等待退出后自动继续、取消后不启动、五分钟超时与重试、设置存储失败与恢复、原生字符串与 Error 拒绝、侧栏握手失败以及普通浏览器边界。固定标签安装包已另行验证实际升级、原账号保留、自动恢复、手动接入和连续打开；标签校验和、来源证明与匿名下载也已核验，详见 [0.1.4 验收记录](acceptance-0.1.4.md)。首次未启用连接的等待、取消与超时由浏览器回归验证，本轮没有退出日常 Codex 来重测该首次流程。
