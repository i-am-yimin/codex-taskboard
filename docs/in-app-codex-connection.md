# 在 Taskboard 内连接日常 Codex

0.1.14 准备发布，将连接详情入口统一到“账号菜单 → 连接与本机”，延续 0.1.13 对日常 Codex、侧栏看板与草稿能力的分别呈现。原生连接成功不等于侧栏已经接入，侧栏暂不可用也不影响任务看板主窗口。本版实际交付范围见 [0.1.14 验收](acceptance-0.1.14.md)；当前公开 0.1.13 的固定包记录保留于[上一版验收](acceptance-0.1.13.md)，历史应用内接入见 [0.1.4 记录](acceptance-0.1.4.md)。

## 日常接入

从 Windows Taskboard 主界面点击“连接 Codex”。已启用连接的日常窗口会被复用；没有运行时，Taskboard 打开正常 Codex 环境，沿用原登录、项目和聊天。0.1.14 主界面与“账号菜单 → 连接与本机”共享同一状态和正在执行的请求；已发布 0.1.13 的对应入口仍为“设置 → 连接与设备”。0.1.14 最终安装包与实机验证尚待完成。

已经运行但未启用连接的 Codex 需要正常重开一次。界面按三步说明：保存工作并正常退出、Taskboard 自动重开原环境、检查并接入侧栏。点击“退出后自动接入”开始等待，可以取消；五分钟未完成会结束等待。Taskboard 不会强制结束日常进程，也不能为任意已打开的进程热开启连接端口。

正在打开或连接的原生请求会先被观察，不重复发起启动。工作区短暂未就绪时，先在有界时间内重新检查当前能力；只有完整身份与结构复核通过后才安装侧栏。等待结束仍未通过时显示具体状态，不以不断重试跳过保护。

## 查看事实与恢复

“连接与本机”分别显示 Codex 桌面、侧栏看板、任务草稿及可用动作，技术原因收在诊断详情中。

- 已接入：主界面提供“打开 Codex”，返回或恢复经过身份复核的原窗口。完整侧栏握手确认后才显示成功。
- 侧栏尚未接入：如果结构已经就绪，可以接入侧栏；如果工作区尚未匹配、存在草稿或弹窗，先检测当前状态并按提示处理。日常草稿不被清空或自动发送。
- 身份异常、目标变化或恢复未确认：停止打开与接入操作，分别显示原因。重新检测不会绕过归属、精确页面或 CSP 恢复检查。
- 暂不接入侧栏：可继续在任务看板主窗口管理任务。连接不是领取、运行、提交或验收的替代动作。

检测和连接都会读取当前事实，不把上次的成功状态作为本次授权。焦点恢复、页面重新可见及已安装后的状态刷新用于发现变化；共享正在进行的检查，避免并发重复操作。浏览器与 Codex 内嵌看板不显示 Windows 原生连接入口。

## 自动连接与设置保存

首次完整接入成功后，Taskboard 记住“启动 Taskboard 时自动连接日常 Codex”。在设置中可以关闭；明确关闭后，手动接入不会重新开启。以后从其他入口打开未启用连接的 Codex，仍需要按说明正常重开一次。

本机存储失败时单独显示“设置未保存”。“重试保存”只重试用户的偏好选择，不再次连接或安装侧栏，不覆盖本次连接结果。

旧连接快捷方式继续兼容，但日常使用无需专用快捷方式。关闭 Taskboard 窗口只会收至托盘，彻底退出使用托盘“退出”；退出时尝试撤回本实例侧栏并恢复原生页面/CSP，保留 Codex 与未发送草稿。

## 兼容范围

生产接入使用有限页面结构契约自检，同一契约内的版本更新无需逐个追加补丁号。新结构仍可能不兼容；任何私有 DOM 接入都不能保证所有未来桌面版本永久支持。未知结构停止接入，任务看板可独立使用；官方 UI 合成原型的独立证据见 [原型说明](codex-plugin-ui-probe.md)，它尚未成为生产接入路线。

日常模式只使用手动复制，不自动填写或发送任务。自动草稿仍限原来已验证的独立测试环境，并要求精确项目、空编辑器与写入确认。独立测试环境保留在设置页的折叠项中，不复制日常登录资料。窗口恢复保留进程、页面和原生窗口核验；多个可见候选继续拒绝。
