# 0.1.3 日常 Codex 接入验收

日期：2026-10-24。状态：固定标签安装器验收完成，已公开为预发布。

本版解决日常已经打开 Codex 却只能另开独立环境的问题。首次启用连接后，持续使用“Codex（任务看板连接）”入口，沿用正常环境的登录、项目和聊天。原图标不带连接参数，不能给任意后续进程热启用连接。日常模式使用手动复制草稿；独立测试环境保留原自动草稿能力。

来源标签：`v0.1.3`，提交：`69c865bbdc5458834a2b0debddc56a283e1dac38`。发布构建：[40067459234](https://github.com/i-am-yimin/codex-taskboard/actions/runs/40067459234)。Windows 安装器 SHA-256：`07948800bb32757e2acd904b9b6c28d41e8931334bf666b56696565200ba3f9d`，签名状态：`NotSigned`。

0.1.2 的固定标签安装器因较长中文路径下的模块格式识别问题而未公开，继续保留草稿与原资产。0.1.3 使用明确的 .cjs 伴随服务和 CLI 入口，并在 Windows CI、标签构建和实际安装中验证；旧失败记录见 [0.1.2 验收](acceptance-0.1.2.md)。

修复过程中的失败证据保留。隐藏 iframe 首次握手和外部刷新恢复曾超时，随后将就绪响应移至 React 布局 effect，没有放宽 nonce、来源、CSP 或握手时限。实际安装发现 Tauri 字符串拒绝说明被通用错误覆盖，已统一保留字符串与 Error 说明。正确入口的首次自动接入未成功，并发操作曾出现生命周期错误；新增挂载等待和共享安装后通过源码、独立 Chromium 与最终实际产品验收。完整 CI 曾发现登录页被当成加载状态而超时，补上即时拒绝后相关完整检查通过。

早期独立测试中的 `Browser.close` 只关闭渲染窗口，主进程仍存活；受控回收不计入正常退出证据。后续另用应用自身退出入口和真实进程句柄完成退出/重启验收。只读观察的首次白帧截图及 CSP 跨域 blockedURI 匹配问题属于观察器失败，原始记录保留，未作为通过证据；已在等待绘制并按来源匹配后重新核实。

最终验收中，只读原生观察曾返回空会话，未执行该轮 CDP 操作；随后在保护不变的情况下重新验证同一进程及页面并通过。快捷方式冷启动的首次观察早于自动接入完成，侧栏尚不存在；保留该失败观察后，仅再次观察已运行的产品，未重开应用或手动重试接入，确认生产侧栏及已同步看板正常。公开页面首次读回曾网络超时，随后以不带认证或 Cookie 的系统 curl 完成页面、安装器及校验和核验。

合成验收服务退出后，测试用 embedded-postgres 的 Windows 停止实现遗留了一个子进程及监听句柄。核对精确创建时间、父进程、命令与专用数据目录后，先尝试 PostgreSQL 终止信号；信号管道不可用，随后受控回收该子进程，保留数据库文件，确认测试端口关闭。此项不计作数据库正常关闭证据，也不替代最终 Taskboard 产品的正常退出证据。

Windows 仍为未签名开发预览，未知宿主版本继续拒绝。生产依赖高危阈值检查通过，仍有低/中危依赖项。服务端独立保持 `0.1.2-preview.1`，本次客户端发布不移动旧标签、不替换旧资产，也不自动升级已有服务端；Linux 归档属于本次客户端源码标签的独立构建。
