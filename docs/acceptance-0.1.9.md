## 诊断方式与过程限制

Windows Computer Use 和浏览器 REPL 在执行代码前均报告 `failed to write kernel assets`，恢复重试仍失败。因此界面交互采用微软支持的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，仅在独立测试进程开启回环调试，并操作实际安装的 Tauri WebView。每次动作核对安装程序路径/PID/创建时间、直接子 WebView、独立 profile、监听归属与唯一精确页面。没有修改安装文件、注册表、CSP 策略或身份门禁。这是实际安装包的 WebView 诊断证据，不能表述为无诊断的原生视觉工具验收。

首轮测试恢复出了先前由验收脚本生成的合成插件提及草稿，产品正确拒绝接入。切到已有合成会话后，宿主同时保留两个编辑器，仍不满足唯一编辑器契约。完整测试 profile 先完成备份，后续以 DPAPI 分块加密并核对解密摘要；仅清理了精确匹配的自建合成插件提及夹具，并另存原始草稿。随后在唯一空编辑器上通过正向接入。没有清理真实草稿。**当前多个编辑器的宿主缓存状态仍会拒绝接入，本轮不声明支持该状态。**

早先出现过原生控制暂未就绪和测试观察超时；先检查原实例，未重复启动安装器或并行创建新的宿主。部分诊断脚本的数组枚举、转译和代理问题已修正，未改产品门禁或固定载荷。独立 Codex 窗口正常关闭后两次留下无窗口进程：已在备份、精确身份和实际 CSP 恢复确认后清理残留；不能把这部分写成 Codex 进程全部自然退出。日常 Codex 的原进程身份始终保持。

恢复普通环境时，一次从 Codex 包上下文直接启动继承了不同的默认 WebView 目录；没有据此认定原环境恢复。该实例已正常退出，随后使用 Windows Explorer 普通入口，核对实际原 profile 后才记录恢复通过。没有删除不明归属的目录。

日常 Codex 配置在此前核对时与基线相同，但最终发现 `config.toml` 于 2026-10-30 03:12:03 UTC 变化。来源未确认，已加密留证并保留现值，未覆盖可能并发发生的修改。**不声明日常 Codex 配置在整个维护期逐字节不变**；日常进程未重启、原 Taskboard 登录/草稿保留分别已有独立证据。
