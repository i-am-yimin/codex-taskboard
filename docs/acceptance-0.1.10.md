日期：2026-10-30。修复 Codex 会话缓存与编辑器延迟挂载造成的侧栏误撤回，以及重载中短时原生证明不可观测造成的恢复失败。经用户明确授权，已从 0.1.9 原位升级到 **0.1.10 未签名本机候选**，完成下述实际安装版验收并恢复原账号环境。尚未公开发布，源码、隔离实机、固定载荷与真实安装的证据分别记录。

## 行为与边界

- 新增 `active-page-cache-shell-v1`，区分唯一当前页和完整隐藏缓存页。每页的 main/editor、归属与隐藏方式均验证，未知额外编辑器、可见缓存页、重复当前页和外部区域继续拒绝。
- 打开看板时重新绑定当前完整工作区，隐藏会话正文和标题栏；保留所有缓存编辑器及同一 iframe。当前 main 已有而 editor 尚未挂载时，恢复原生视图、禁用入口并在原有预算内等待；该中间态不授予能力。
- 刷新与恢复都重新检查结构和同一原生身份。短时空 session / negative proof 只在原 4 秒 / 8 秒预算内完整复核一次，不复用旧成功、不改绑目标。
- CSP 刷新保护所有缓存草稿，包括隐藏文字、空格、图片和富文本。自动草稿版本、项目和空编辑器模型门禁不增加；日常模式仍为用户手动复制与确认发送。
- 本轮不改变任务 API、数据库、生产服务或官方 UI 原型的业务接入范围，没有模型调用。

### 诊断方式与过程限制

Windows Computer Use 初始化两次均在执行前报告 `failed to write kernel assets`。实际界面使用微软支持的 WebView2 回环诊断参数，仅对独立测试进程启用；每次绑定核对真实安装路径/PID/创建时间、直接子 WebView、独立 profile、回环监听者和精确页面。真实 Codex 则通过仓库原生模块复核后绑定其独立主页面。没有改安装文件、CSP 策略或产品身份门禁；此处是实际安装版的 CDP/WebView 诊断证据，不是 Windows 原生视觉工具验收。

早期诊断包含过早读取 companion/WebView 退出状态、独立备份路径表达式与外链拒绝、草稿状态文本选择器不匹配，以及原生项目行小图标被遮挡。没有因此重复启动应用或安装器、清空草稿或强制点击遮挡控件；改用可见的“新聊天”入口及明确状态节点。一次未结束导航诊断与后续操作发生交叠，结果已废弃；另有诊断在取得隐藏 iframe 引用前停住，原客户端已精确回收。最终改为核验实际 DOM iframe 节点身份，并串行完整重验通过。原失败、步骤跟踪、废弃记录和最终成功回执各自保留，不把中途结果改写为通过。

本轮没有新增模型消息，也没有运行官方 CLI 模型、生产任务写入、服务器迁移或公开发布。原生编辑器保持既有空内容；隐藏富文本/空格草稿阻止刷新由源码正负回归覆盖，不把本轮最终包实机表述为输入过这些原生聊天草稿。
