# ADR 0003：受管理 Codex 的进程归属契约

状态：拒绝路径、原生进程证明、私有交接及重启保护已实现；26.924.1866.0 隔离宿主、草稿及原生包上下文交接已通过，已安装程序联合验收待完成。

日期：2026-09-25。

## 背景

适配器原先接受 `managedProcess: true`，伴随服务还能从 `TASKBOARD_MANAGED_CODEX=true` 构造该配置。这个值只能表达调用者意图，不能证明 CDP 监听者确实是 Taskboard 启动的 Codex。虽然安装流程还要求精确目标绑定，进程归属本身仍未得到验证。

当前 Windows 安装的 Codex 为 `26.924.1866.0`。版本号、页面名称或可连接的 CDP 端口都不能单独证明兼容；当前版本的隔离宿主、CSP 和草稿实测结果见[验收记录](../acceptance.md)。

OpenAI 官方的[插件概念文档](https://developers.openai.com/plugins/concepts/plugins)列出 Codex 可安装的 Skill、MCP 服务与生命周期 hook，并将可选 UI 作为 MCP 资源；其中明确介绍的是 ChatGPT 对 MCP Apps UI 的支持。该文档没有给出修改 Codex 原生侧栏或通过 CDP 放宽 CSP 的公开契约。因此现有内嵌路线仍按版本绑定的实验能力验收；后续可单独评估插件界面是否满足产品需求。

## 决策

适配器只接受一个能重复调用 `verify()` 的启动器归属对象。缺少对象、验证失败或验证抛错均返回不可用。伴随服务不再由环境变量构造受管理适配器。当前单元测试使用替身归属对象；这不等于启动器已提供真实证明。

后续由 Tauri 启动器建立真实归属对象，至少绑定以下事实：

1. 启动器实际创建并持续持有的 Codex 子进程句柄、PID 与创建时间，及独立的 Codex 数据目录。
2. 随机选择的字面回环 CDP 地址与监听端口；操作系统报告的监听者必须仍是该子进程。
3. 从该端口发现且唯一匹配的 `targetId`、精确页面 URL 和页面 WebSocket；连接后再通过 `Target.getTargetInfo` 核对。
4. 安装包版本须在已经实机验证的允许清单中。升级后的版本单独复验，不继承旧版 DOM 标记、CSP 或项目身份结论。

上述证明由启动器通过独立回环控制通道交给伴随服务；控制密钥与网页渲染进程持有的浏览器能力凭据分离。控制端持有真实子进程句柄，每次查询重新核验进程、监听者和页面；伴随服务对照首次会话描述并重复查询。进程退出、端口换主、目标漂移或启动器失联时立即撤销。项目绝对路径和完整 Codex 会话仍只保留在本机。

适配器在探测、连接后、首次 CDP 命令前、CSP 修改前、界面注入前及重载恢复前重复检查归属。失效后停止新的页面操作，并使用原有连接尝试清理本实例的 DOM 与 CSP；清理未得到实际确认时报告“恢复未确认”。`openDraft()` 只使用私有会话提供的 `codexHome` 对照可见项目 ID 与请求目录，在唯一空编辑器、无弹窗且目标仍精确匹配时填入，随后保留未发送文字。已安装看板在草稿前先退出并恢复 CSP。`listProjects()` 与 `openThread()` 继续保持不可用。

## 2026-09-25 原生实现边界

Tauri 已有一个尚未接入界面的 `start_managed_codex` 命令。它只读取系统登记的已验证 MSIX 版本，创建独立目录并保留实际子进程句柄和创建时间；Windows TCP 表必须显示字面回环监听端口归该 PID，唯一主页面及 WebSocket 也必须精确匹配。绑定超时或漂移时不把该进程交给适配器；只要原有子进程仍在运行，启动器保留句柄并拒绝另起第二个实例。

后续增量已建立私有控制通道。原生控制端返回会话 ID、固定版本、PID、创建时间、隔离 `codexHome`、回环端点与精确页面绑定；伴随服务创建的 `ManagedCodexOwner` 在每次 `verify()` 时重新查询。浏览器能力凭据不能访问该控制端。退出 Taskboard 时保留独立 Codex 与其可能存在的未发送草稿，并持久记录 PID 和创建时间；重启时若旧进程仍运行就拒绝启动第二个实例。记录损坏或无法判定进程状态时拒绝启动。当前 `26.917.9434.0` 已在脚本启动的隔离宿主通过看板内部交互、重载恢复、实际 CSP 恢复和草稿成功及拒绝路径；版本清单已开放当前版本。安装程序的 Tauri 私有交接、退出和重启仍需联合复验。

## 验收矩阵

### 2026-09-26：包上下文启动契约

新版本直接运行安装目录的 exe 未能进入主页面；Windows 自带 `Invoke-CommandInDesktopPackage -PreventBreakaway` 在正确包上下文中启动隔离辅助进程后，实际子进程的包身份、独立目录、回环端口与主页面均通过核验。该命令只验证了可行性，不能把辅助脚本返回的 PID 当作实际进程句柄的替代品。

基础层现已实现 `OwnedProcess`。跨进程接收入口通过已认证辅助进程的句柄执行 `DuplicateHandle`，再精确核验进程创建时间、PID、可执行路径和包身份；本层不负责建立或认证辅助通道。真实测试进程间的句柄复制、源副本释放、子进程退出撤销与身份拒绝已通过。释放句柄不会终止可能含草稿的 Codex。

Taskboard 现已提供专用辅助入口，先于 Tauri 单实例初始化分流。`private_pipe.rs` 创建随机名称、仅当前用户 DACL、拒绝远程连接、独占首实例的命名管道；双方通过系统报告的通信方 PID 取得句柄并核验可执行文件，辅助入口还必须具有精确的 Codex 包身份。主进程确认会话与隔离参数后，辅助入口创建 Codex 并持续持有子进程句柄。主进程通过 `DuplicateHandle` 取得同一进程对象，再核对创建时间、包身份、可执行路径；监听者与唯一页面仍由既有绑定检查核验。共享 JSON 只用于防止重复启动，不用于授予归属。

交接通道与已有网页及伴随服务控制能力分离。45 秒总截止时间及 32 KiB 消息上限约束辅助通道；会话仅处理一次配置、回执和确认。启动前独占写入 `pending` 记录，创建子进程后通过原子替换持久化 `active` 身份；预留记录损坏、写失败或交接未确认时保留记录并拒绝再次启动。交接失败不自动终止可能已有草稿的子进程。尚未确认的 `pending` 记录需要人工核对，不能单凭原主进程退出就清除。必须覆盖辅助进程超时或退出、重复回执、伪造 PID、包身份变化、主进程在创建后退出、记录写失败、已有未发送草稿时重启等失败路径。未完成交接不得开放 CSP 或草稿。

原生模块诊断已通过真实包上下文启动、持有权交接、TCP 归属及唯一主页面检查，主诊断进程退出后子进程保留。结合先前宿主与草稿证据，开发预览原生版本门禁现更新为 `26.924.1866.0`；已安装程序的完整交互、草稿和退出重启仍按 G1 单独验收，不能用模块诊断替代。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 只有环境变量或 CDP 端口 | 伴随服务不启用适配器，安装请求拒绝 |
| 归属对象缺失、返回 false 或抛错 | 探测不可用，不连接 CDP |
| 连接期间归属撤销 | 关闭新连接，未发送页面协议命令 |
| CSP 或注入前归属撤销 | 不修改页面，已有连接进入清理流程 |
| 进程退出、端口换主、目标漂移 | 不重新注入；记录实际清理和恢复结果 |
| Codex 版本不在允许清单 | 拒绝探测和安装，不因 UI 外观相似而放行 |
| 真实已安装版本的成功路径 | 记录进程、端口、目标、可交互看板、项目身份、未发送草稿及退出后 CSP 恢复证据 |

目前自动测试覆盖控制通道的认证、归属撤销和重启时存活进程的拒绝，但尚无已安装程序的端到端成功结果。项目映射依赖 Codex 的内部 SQLite 结构和随包 Node 22 的实验性 `node:sqlite` 接口，必须按宿主与运行时版本重新验证；草稿操作会再次核对可见项目、目标路径、唯一空编辑器与页面绑定。隔离宿主结果和待完成的安装程序联合验收以[闭环验收计划](../closure-acceptance.md)和[验收记录](../acceptance.md)为准。


### 2026-10-08：重复启动时恢复原生窗口

重复启动的所有权核对同时用于窗口恢复。窗口来源只能是持有的子进程句柄；renderer 不提交 PID、HWND 或窗口标题。枚举结果必须为唯一的无 owner `Chrome_WidgetWin_1` 顶层窗口，排除工具窗口、不可激活窗口、子窗口和 cloaked 窗口。执行显示与焦点动作前重新核对进程/页面绑定和窗口元数据，拒绝歧义或身份漂移。隐藏窗口可以恢复，最小化窗口使用恢复动作，已有最大化窗口保留尺寸。显示失败不能报告成功；Windows 拒绝前台焦点时保留可见窗口并给出任务栏提示。


### 2026-10-17：正常退出后的适配器退休

已安装版 d841a64 的真实窗口通过“文件 → 退出 ChatGPT”释放了原生进程、启动助手及监听端口。随后从同一安装窗口重新启动时，伴随服务仍尝试恢复已消失的旧页面，把清理失败永久锁定为 `RESTORATION_UNCONFIRMED`，阻止新会话接入。该失败保留在安装版验收证据中，不能以正常退出已经完成代替重接通过。

启动器新增私有的 `/exited/<session>/<pid>/<createdTicks>` 查询。只有持有的 Windows 进程对象被信号触发才能证明退出；端口消失、页面漂移、PID 相同或查询失败均不构成退出证据。替换会话前核对旧句柄的退出信号，将精确会话、PID 和创建时间凭据保留在内存中，并传递给新的受管理实例，最多保留最近 64 份。启动失败时继续保留原对象和凭据。

伴随服务清理旧页面失败后，仅在私有启动器确认该旧进程已退出时退休旧适配器。缺少凭据、凭据不匹配、旧进程仍存活或控制通道异常时继续拒绝接入；以后取得同一旧进程的退出凭据时允许恢复。并发请求共用一次适配器切换，新适配器仍逐次检查原生归属、精确目标和项目条件。自动回归与新安装包实测结果分别记录，尚未用源码修复宣称安装版复验通过。

### 2026-10-17：普通重启保留独立登录与项目配置

用户报告安装验收中反复要求登录。e91d999 的两次真实启动记录证明：每次旧进程退出后，启动器生成新的随机目录，profile 和 codex-home 均为空；包上下文助手还会拒绝非空目录。旧目录中的状态未删除，但普通重启没有复用。

启动器现在在 managed-codex/profile.json 中登记一个随机的专用子目录，并在后续普通启动复用同一 profile 和 codex-home。登记只包含格式版本与相对目录名，不包含凭据；主 Codex 的数据不读取、不复制。启动器与包上下文助手都验证登记、规范路径和目录边界，拒绝目录联接或符号链接、记录损坏、缺少已登记目录以及任意替代路径；不会静默重置为新的登录环境。旧版遗留的随机目录保持原样，不扫描账号或自动选择其中一套；如需迁移，只能在确认旧实例退出后显式登记已核对的专用目录。

目录持久化不授予进程归属。每次启动仍生成新的会话能力和回环端口，持有新的 Windows 进程句柄，核对 PID、创建时间、包身份、监听者及精确页面绑定。上次进程仍在运行、启动尚未确认或进程状态无法判定时，继续拒绝新启动。完整重启验收须证明登录、项目和未发送草稿保留；全新目录首次登录作为独立场景，不能替代普通重启。自动回归与安装版实机结果分别记录；本段说明实现，尚不宣称 G1–G3 通过。
