# ADR 0004：接入日常 Codex

日期：2026-10-24。状态：0.1.3 已通过固定标签安装器、日常 profile 与正常重连验收，并公开为预发布。

原流程只允许连接启动器创建的独立环境。“接入 Codex 侧栏”的名称没有说明这一前提，导致已经打开 Codex 的用户仍需另外登录、打开项目。

日常接入改为首选入口，独立环境保留在“独立测试环境”折叠项。发现已运行但没有 CDP 连接端口的日常窗口时，明确提示保存工作并正常退出一次；不结束用户进程，不热启用调试，不自动重载未验证的页面。无现有进程时，在已安装 MSIX 的正常包上下文中启动，增加字面回环调试端口，不传独立 profile 参数，不复制登录状态。恢复用户/系统级 Codex 环境设置，清除来自 Agent 会话和 Taskboard 的临时变量。

用户可显式创建开始菜单中的“Codex（任务看板连接）”快捷方式。它启动 Taskboard，并连接或打开同一个日常 Codex，再调用既有的经过认证的侧栏安装接口。继续使用原先不带连接参数的 Codex 入口时，仍可能需要正常退出后从连接入口打开；一次配置不能给任意后续启动的进程热开启 CDP。

0.1.4 源码将连接入口直接放到 Taskboard 主界面，并把状态、等待退出和自动恢复收在应用内。接入成功后的本机偏好保存在默认 WebView profile，普通 Taskboard 启动即可执行同一原生连接与受认证安装流程；用户可关闭自动连接。等待退出只查询状态，可取消且有五分钟上限，不发送退出命令。旧快捷方式仅作兼容入口，不再要求用户使用。详见[应用内接入说明](../in-app-codex-connection.md)。

这条路线增加了不同于 ADR 0003 的进程来源：本机原生代码发现的日常实例。不会把它声称为启动器创建的子进程。原生层必须核对当前用户安装的 OpenAI 包、精确可执行路径、Windows 会话和用户 SID，并持续持有只有查询/同步权限的真实进程句柄。每次适配器操作仍重复验证创建时间、进程身份、字面回环监听者和唯一精确页面绑定。多个主进程、多个 CDP 页面、归属变化或恢复未确认时停止。网页不得提供 PID、目录或调试地址。Taskboard 重启后可重新发现并验证尚在运行的日常实例。

私有会话描述新增 `mode: daily`，不携带推测的 `codexHome`。日常侧栏与自动草稿能力分开：在自定义 Codex home 尚不能可靠辨认前，日常模式只开放侧栏，任务草稿使用现有手动复制流程。独立模式保留原有项目/空编辑器验证和自动草稿能力。退出 Taskboard 时仍尝试恢复 DOM/CSP，保留 Codex 与未发送草稿。

宿主兼容版本清单继续生效。2026-10-24 先只读确认日常 `26.1016.8622.0` 未启用调试端口，再使用已有的登记验收目录完成该精确版本的原生句柄/监听/页面检查和侧栏功能测试，清单仅增加这一精确版本。日常 profile 与最终安装包已分别完成验收。OpenAI 官方的 [App Server 文档](https://learn.chatgpt.com/docs/app-server)描述代理协议连接，不能作为修改桌面原生侧栏的公开接口契约。

新宿主实测发现隐藏 iframe 的初次加载和外部刷新恢复会偶发就绪超时。就绪响应改为在 React 提交后的布局 effect 中注册，避免依赖隐藏 iframe 的首次绘制；仍检查来源、父窗口和 nonce，握手时限不变。新增隐藏原生布局及刷新后的真实 React 回归，安装/恢复错误也区分宿主标记缺失与看板就绪超时。保留两次修复前实机失败记录；修复后真实侧栏、外部刷新、撤销后的实际 CSP enforce、nonce 失败清理、项目/弹窗拒绝、六段未发送草稿 DOM/模型一致和重复写入保护通过。

源码验证覆盖私有日常会话不推测 home、独立会话目录要求、未知版本拒绝、前端首次重开提示及模拟的正常窗口接入流程。类型检查、相关 ESLint 检查、Web/服务端构建、完整 Tauri `cargo check --release --tests` 通过。原生模块测试 40 项通过、5 项按原有条件忽略；私有控制/适配器退出回归 11 项通过；连接页浏览器回归 2 项通过，包含窄窗口按钮可见性。实际运行只读原生探针，正确报告本机 `26.1016.8622.0` 为 `restart-required`。

真实日常环境的启动、原登录/项目/聊天保留、产品安装的侧栏、正常退出后的实际 CSP enforce、连接快捷方式及同一 Codex 进程重连均已验收。固定标签的实际安装器另行通过旧版伴随服务数据升级和日常安装升级。只读原生探针、隔离宿主和最终交付各自的证据范围见 [0.1.3 验收](../acceptance-0.1.3.md)。

早期内部版本为 `0.1.1` 的本地候选仅属于流程开发证据。固定 `0.1.2` 安装包首次启动失败，因此保留草稿与原资产，记录见 [0.1.2 验收](../acceptance-0.1.2.md)。后续 `0.1.3` 固定标签安装器完成实际升级、同进程重连和公开下载核验，现已公开为预发布，既有标签和资产保持。最终状态见 [0.1.3 验收](../acceptance-0.1.3.md)。
