# ADR 0002：受管理页面的 CSP 初始化与恢复

状态：开发预览实施中，完整 Codex 实机闭环待验收。

日期：2026-09-09。

## 背景

Codex `26.901.5280.0` 的 `frame-src` 阻止本机 HTTP 看板。真实独立测试页面中，`Page.setBypassCSP(true)` 返回成功后，当前文档仍显示 `ERR_BLOCKED_BY_CSP`；设置后重载才解除拦截。恢复 false 后也需要新文档才能重新触发策略。协议响应不能证明当前文档已恢复。

## 决策

仅对用户明确开启的受管理测试页面启用此能力。启用说明必须覆盖整个页面的 CSP 影响和重载行为，不能描述为仅放行看板地址。`allowCspBypass` 与 `allowCspReload` 分开表达意图；缺少安全重载契约时不进行此初始化流程。

每次重载前检查精确页面绑定、唯一宿主和编辑器标记、空白编辑器以及没有对话框。检查与重载之间保持最短命令路径，并在异步边界检查当前操作是否已取消。重载后验证文档确实更换，再等待宿主界面就绪，最后通过随机 nonce、准确来源和 iframe 窗口验证看板已挂载。

退出时移除自有界面，尝试设置 false，再按相同保护条件重载。用户已输入新草稿或打开对话框时保留当前文档，明确报告恢复未完成；不能为了恢复策略而丢弃草稿。命令失败、连接失联或超时也不得报告恢复成功。新会话不能与旧会话的启用、恢复命令交错。

进程所有权由启动器的实际子进程、独立 profile、回环监听归属和目标绑定共同证明。配置中的布尔值不能代替所有权证明。适配器测试或手工实验也不能代替安装后的完整生命周期验收。

## 验证与限制

自动化覆盖独立 Chromium 的策略初始化、真实就绪握手、重载恢复及草稿保护；Codex 实机还需独立验证看板交互、退出和实际 CSP 拦截恢复。具体执行结果以 [验收记录](../acceptance.md) 和 [宿主验证记录](../codex-host-verification.md) 为准。

该流程不增加项目管理能力，也不自动发送任务。项目路径身份、草稿填入、启动器接入和安装包组合验收仍是独立发布门槛。
